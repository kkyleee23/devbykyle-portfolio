05<ABOUT/>

I came at this backwards. I was building apps and games before I got curious about how websites worked, and then I decided I wanted both instead of picking one. I still reach for plain HTML and JavaScript more often than a framework, because I learned to make things run before I learned to make them look right.

Backend is the half I care about most. The data model, the API, and the pipeline that turns an upload into something a person can use. I learned the front end because a tool nobody can open is not finished, and because on a small project there is usually only one person to build both.

The first things I made were for school, since that was the problem in front of me. The work is not limited to that. A capstone team that needs a backend, a small company that needs an internal tool, or one person who needs something that does a single job properly. Those are all the same problem shaped differently.

I pick up design from wherever it turns up, and I send small fixes to open-source projects when I notice something broken. Two years of this so far, all self-taught, all outside class hours.

07<SELECTED-PROJECTS/>

01 Live

Planora

A free task manager for Android and web with a built-in AI assistant called Nora. Tasks, notes and goals in one place. No accounts, no ads, and it works with the network off.

  • Under 5 MB
  • Works offline
  • No account
  • Android + Web
  • HTML
  • CSS
  • JavaScript
  • Vercel
Visit site — PlanoraSource — Planora
The problem
I kept losing track of my own work across three different apps, and every planner I tried wanted an account before it would show me a single screen.
What I did
Local-first storage, so the app opens straight into your board with nothing to sign up for. No build step at all, which keeps the whole thing under 5 MB and means it loads on a bad connection.
What broke
Nora, the assistant, answers without enough of the board in front of it, so its suggestions are generic. That is a context problem rather than a model problem, and it is what I am rebuilding now.
What is next
Give Nora the actual task state before it answers, and add a proper sync path for people who do want their board on two devices.
02 Redeploying

PrintScreen

Upload a PDF, PPTX, DOCX, XLSX or image and get back a structured reviewer: a summary, key terms, flashcards and a practice quiz. Parsing runs on the server before anything reaches a model.

  • 5 file types
  • Express API
  • Groq + Gemini
  • Node.js
  • Express
  • Groq
  • Gemini
  • Render
Source — PrintScreenPreview — PrintScreen
The problem
Revising meant re-reading slide decks the night before an exam, which is slow and does not tell you what you actually forgot.
What I did
Extract text per format on the server, then send clean text to a model rather than raw files. PPTX has no parser worth using, so it unzips the archive and reads the slide XML directly.
What broke
The deployed build asks each visitor for their own API key, which makes it look broken to anyone who opens it cold. Free tier hosting also sleeps, so the first request waits about twenty seconds.
What is next
Move the key server-side, keep the instance warm, and cap the context so a forty slide deck does not blow the window.

03 Building

Studs

Student and teacher management that runs outside the LMS a school already has. Attendance, activities and scores in one place, without waiting on IT to provision anything.

  • 8 screens
  • Repo-per-entity data layer
  • No framework
  • Vite
  • JavaScript
  • Supabase
  • PostgreSQL
Source — Studs
The problem
Recording attendance and scores took more clicks than it should, and the school system made simple things slow enough that people kept paper backups.
What I did
One repository module per entity, so every page talks to a data layer instead of reaching for the database directly. That keeps queries in one place and makes each page short enough to read in a sitting.
What broke
The first version put Supabase calls inside the pages. Adding a second screen meant copying query logic, and a schema change meant editing five files.
What is next
Finish the reports view, then move the database to a fresh project with row level security switched on from the start.
